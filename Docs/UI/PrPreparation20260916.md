## PR 전 정리 순서

UI 전용 변경 묶음과 실제 PR 본문 초안은 `UiReviewPullRequest20260916.md`를 확인한다. 패키징은 실제 브랜치/파일/스테이징을 변경하지 않는다.

1. 기존 미커밋 작업을 별도 보존하고 UI 변경 목록 및 `.meta` 쌍을 확인한다.
2. 최신 dev를 기준으로 팀 원본 파일이 변경/삭제되는 diff가 없는지 확인한다. 지금 브랜치는 원본 의존성 파일만 반영했으며 dev 이력을 병합한 상태가 아니다.
3. 공유 폰트의 기존 미커밋 변경은 소유자 확인 없이 포함하거나 되돌리지 않는다.
4. UI 기능 단위로 변경을 정리하고 컴파일·Play 검사를 다시 수행한 뒤 커밋/푸시한다.
5. `base: dev`로 리뷰 PR을 연다. 전체 게임 통합은 미완료임을 명시한다. 머지는 하지 않는다.

팀 파일을 대량으로 되돌리는 PR이 되지 않도록, 단순히 모든 변경을 선택해 커밋하거나 현재 브랜치의 오래된 HEAD만으로 PR을 만들지 않는다. 안전한 이력 정리는 미커밋 파일 보존 후 별도 작업으로 진행한다.
