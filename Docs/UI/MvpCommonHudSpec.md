# MVP 공통 HUD 명세

## 목표

3개 웨이브로 구성된 MVP 핵심 루프를 진행하고 검증하는 데 필요한 최소 UI를 제공한다.

`건설 -> 전투 -> 보상 -> 건설 또는 결과`

HUD는 재화·코어·웨이브 시스템이 소유한 실제 데이터를 표시한다. UI 내부에 게임 상태의 별도 원본을 만들지 않는다.

## MVP 범위

### 상시 HUD

- 현재 골드
- 현재 웨이브와 전체 웨이브 수 (`1 / 3`)
- 현재 Phase (`건설`, `전투`, `보상`, `결과`)
- 웨이브 시작 버튼

### 웨이브 결과

- 승리 또는 패배
- 완료한 웨이브에서 획득한 골드
- 다음 웨이브가 남은 경우 계속하기
- 최종 결과 이후 다시 시작하기

### 후속 MVP UI

- 건물 선택·건설·1회 업그레이드·해체 UI
- 건물·유닛 정보창 및 건설 공간 해금 선택 UI
- 생존 유닛 수와 관문·베이스캠프 상태 표시: 데이터 계약 확정 후 추가

아래 항목과 달리 위 UI는 4주차 MVP에서 제외하지 않는다.
2026-09-08 후속 작업으로 건물 선택·정보 **표시 패널과 별도 테스트 씬**을 추가했다.
건물 담당의 실제 선택 이벤트·건설 동작 연결은 미완료이며, 규격과 검증 상태는 `BuildingInfoUiSpec.md`, `BuildingInfoUiValidation.md`에 정리한다.
이후 건물 행동 UI와 유닛 정보 UI도 로컬 표시/입력 검증을 완료했다. 실제 게임 시스템 연결과 시설 상태·공간 해금 UI는 남아 있다.
유닛 정보 연결 제안과 검증 상태는 `UnitInfoUiSpec.md`, `UnitInfoUiValidation.md`를 참조한다.

### MVP 이후 확장 범위

- 보석과 혈석
- 분기와 노드 진행
- 제단 스킬과 마나 UI
- 아티팩트 선택
- 상점과 이벤트 UI
- 최종 그래픽·애니메이션·사운드

## 표시 상태

| Phase | 골드 | 웨이브 | 시작 버튼 | 결과 패널 |
| --- | --- | --- | --- | --- |
| 건설 | 표시 | 표시 | 웨이브 시작 가능 시에만 활성화 | 숨김 |
| 전투 | 표시 | 표시 | 숨김 또는 비활성화 | 숨김 |
| 보상 | 보상 적용 후 값 표시 | 표시 | 비활성화 | 웨이브 결과 표시 |
| 결과 | 표시 | 마지막 웨이브 표시 | 숨김 | 최종 결과와 다시 시작 표시 |

Phase 전환은 코어 시스템이 담당한다. HUD는 전달받은 Phase를 화면에 반영하기만 한다.

## 필요한 데이터 계약

### 재화 담당: 홍재희

| 데이터 또는 알림 | UI 사용 목적 |
| --- | --- |
| 현재 골드 | 골드 HUD 표시 |
| 골드 변경 이벤트 | 값이 바뀔 때만 HUD 갱신 |
| 웨이브 보상 골드 | 웨이브 결과 표시 |

### 코어·웨이브 담당: 문규성

| 데이터 또는 알림 | UI 사용 목적 |
| --- | --- |
| 현재 Phase | HUD 상태 선택 |
| 현재 웨이브 번호 | 현재 진행도 표시 |
| MVP 전체 웨이브 수 | `현재 / 전체` 표시 |
| 웨이브 시작 가능 여부 | 시작 버튼 활성화 상태 결정 |
| 웨이브 종료 결과 | 웨이브 결과 패널 열기 |
| 한 판 종료 결과 | 최종 결과 패널 열기 |

### 건물 담당: 김도현

| 데이터 또는 알림 | UI 사용 목적 |
| --- | --- |
| 유닛 생산 건물 보유 여부 | 코어 시스템의 시작 가능 검사에 사용할 수 있는 조건 |
| 건설 조작 잠금 상태 | 전투 중 건물 UI 잠금 표시 |

HUD가 건설 조건을 직접 조합하지 않고, 코어 시스템이 최종 결정한 웨이브 시작 가능 여부를 전달받는다.

## UI 요청

HUD는 플레이어의 의도만 전달하며 게임 상태를 직접 변경하지 않는다.

| 요청 | 수신 담당 | 완료 전달 방식 |
| --- | --- | --- |
| 웨이브 시작 요청 | 코어·웨이브 시스템 | Phase 변경과 웨이브 시작 알림 |
| 계속하기 요청 | 코어·웨이브 시스템 | 건설 또는 필요한 다음 Phase로 변경 |
| 다시 시작 요청 | 코어 시스템 | 게임 초기화 후 최초 HUD 데이터 전달 |

실패한 요청은 게임 상태를 일부 변경한 채로 남겨서는 안 된다. 실패 이유가 전달되면 HUD는 임의의 규칙을 만들지 않고 전달받은 메시지를 표시한다.

## 상호작용 규칙

- HUD를 비활성화했다 다시 활성화해도 버튼 클릭이 한 번만 처리되어야 한다.
- 웨이브 시작 요청을 처리하는 동안 시작 버튼을 비활성화한다.
- 보상 골드는 HUD에서 계산하지 않고 전달받은 결과를 표시한다.
- 재화 시스템이 보상을 적용한 뒤 골드 표시를 갱신한다.
- 최종 결과 화면과 각 웨이브의 보상 패널을 구분한다.
- 사용할 수 없거나 구현되지 않은 기능은 비활성화하거나 숨긴다.

## 기준 해상도

- 제작 기준: 1920 x 1080
- 앵커와 `CanvasScaler`를 사용해 다른 16:9 해상도에서도 상시 HUD를 읽을 수 있게 한다.
- 더 넓거나 좁은 화면 비율은 이후에 별도로 점검한다. 플랫폼 안전 영역 기준은 아직 확정되지 않았다.

## 완료 조건

- 매 프레임 확인하지 않고 골드 변경 시에만 표시가 갱신된다.
- 1웨이브부터 3웨이브까지 현재 웨이브가 정확하게 표시된다.
- 건설 Phase이며 코어 시스템이 허용할 때만 웨이브 시작 버튼이 활성화된다.
- 전투 시작 요청이 중복으로 전달되지 않는다.
- 웨이브 결과에 승패와 전달받은 골드 보상이 표시된다.
- 최종 결과에서 다시 시작할 수 있다.
- HUD를 다시 활성화해도 버튼 이벤트가 중복 등록되지 않는다.
- 선택 데이터가 누락되어도 예외가 발생하지 않는다.
- HUD에 재화·보상·웨이브·패배 조건 계산을 넣지 않는다.

## 현재 구현 기준 (2026-09-08)

- 기존 디렉터리 `Assets/Scripts/UI`, `Assets/Prefabs/UI`, `Assets/Scenes/Test`를 유지한다.
- UI 네임스페이스는 `Game.UI`. uGUI + TextMeshPro + Input System UI 모듈을 사용한다.
- 프리팹: `Assets/Prefabs/UI/MvpCommonHud.prefab`.
- 독립 테스트 씬: `Assets/Scenes/Test/MvpHudTest.unity`. 기존 팀 씬과 Build Settings는 변경하지 않는다.
- 한국어 글꼴은 Noto Sans CJK KR Regular, SIL OFL 1.1 라이선스 원문을 함께 보관한다.
- UI는 승패 조건을 결정하지 않는다. 기존 기획서의 관문 돌파/베이스캠프 파괴 등 서로 다른 서술은 코어 담당자와 확정해야 한다.
- 보상 패널은 수동 계속하기를 지원한다. 자동 진행으로 결정되면 코어 어댑터에서 숨기고 진행한다.
- 테스트 씬의 100 골드·30 골드 보상·3웨이브는 UI 확인용 임시값이며 게임 밸런스 데이터가 아니다.

## 공개 API와 처리 계약

| API | 호출자 / 의미 |
| --- | --- |
| `Initialize()` | 연결 후 표시·요청 잠금·패널 초기화. 값은 `--`로 표시하고 시작을 잠근다. |
| `SetGold(int)` | 재화 담당자의 실제 잔액, 0 이상. UI가 보상을 더하지 않는다. |
| `SetWaveProgress(int, int)` | 웨이브 담당자의 1부터 시작하는 현재 번호와 총 개수. |
| `SetPhaseLabel(string)` | 코어가 결정한 상태의 한국어 표시명. 이것만으로 버튼을 허용하지 않는다. |
| `SetWaveStartInteractable(bool)` | 시작 요청 처리 완료/거절에 대한 응답 및 현재 허용 여부. 매 프레임 호출하지 않는다. |
| `ShowWaveReward(int, bool)` | 확정된 이번 웨이브 보상, 다음 웨이브 존재 여부. 계속하기 요청 잠금을 초기화한다. |
| `HideWaveReward()` | 코어가 다음 준비 단계로 실제 진입했을 때 닫는다. |
| `ShowRunResult(bool, int)` | 최종 승패와 이번 판 획득 골드. 재시작 요청 잠금을 초기화한다. |
| `HideRunResult()` | 결과 패널 닫기. 새 판 시작 시에는 `Initialize()` 권장. |
| `ShowMessage(string)` / `HideMessage()` | 전달받은 실패 사유 표시/닫기. 공백 메시지는 숨김. |

숫자 인수가 계약을 위반하면 `ArgumentOutOfRangeException`을 발생시키며 표시를 부분 변경하지 않는다. 잘못된 게임 데이터를 0으로 조용히 보정하지 않는다.

| UI 이벤트 | 코어 어댑터의 처리 및 응답 |
| --- | --- |
| `WaveStartRequested` | 가능 여부를 다시 검사하고 시작을 시도한다. 성공 시 상태/버튼을 갱신하고, 실패 시 메시지와 `SetWaveStartInteractable(현재 허용 여부)`를 반드시 보낸다. |
| `ContinueRequested` | 다음 단계로 실제 이동 후 보상 패널을 닫고 HUD를 갱신한다. 실패 시 사유와 같은 `ShowWaveReward(...)`를 다시 보내 재시도를 허용한다. |
| `RestartRequested` | 실제 게임 초기화 완료 후 `Initialize()` 및 최초 데이터를 보낸다. 실패 시 사유와 같은 `ShowRunResult(...)`를 다시 보내 재시도를 허용한다. |

이벤트를 구독한 다음 초기 데이터와 버튼 허용 여부를 보내야 한다. 수신자가 없으면 실행 버튼을 활성화하지 않는다. 세 요청은 응답 전까지 동일 버튼을 잠근다. UI 활성화/비활성화를 반복해도 리스너를 중복 등록하지 않는다.

## 코어 브랜치와의 연결 지점

`origin/feature/core-game-test`의 `17f404f`에서 읽기 전용으로 확인한 현재 코드는 `Game.Core.GameFlowController`이다. 해당 코드는 UI 브랜치에 아직 병합되지 않았으므로 오늘 프리팹에 직접 참조하거나 임의로 복제하지 않는다.

| 실제 코어 멤버 | 연결 제안 |
| --- | --- |
| `PhaseChanged`, `CurPhase` | 어댑터에서 `None→연결 대기`, `Preparation→건설`, `BattlePreparing→전투 준비`, `Battle→전투`, `Reward→보상`, `Finished→결과`로 표시한다. |
| `TryStartWave()` (`UniTask<bool>`) | `WaveStartRequested` 수신 시 await하고 성공/실패를 HUD에 응답한다. 예외/취소도 잠금 상태를 복구한다. |
| `CanEnterBuildMode()` | 현재는 건설 모드 허용 검사다. 생산 건물 등 최종 시작 조건과 동일하다고 간주하지 않는다. |
| `CompleteWave()` | 코어 쪽 웨이브 종료 진입점. UI의 계속하기 버튼에 곧바로 연결하면 안 된다. |

계속하기·재시작 완료 알림, 확정 보상/웨이브 번호, 생산 조건 검사를 포함한 시작 가능 여부는 담당자와 추가 합의한다. 합의 전에는 테스트 씬의 `Game.UI.Samples.MvpHudSample`만 임시 데이터 공급자로 사용한다.

## 팀원이 확인하는 방법

1. Unity 6000.3.23f1에서 `MvpHudTest` 씬을 열고 Play한다.
2. 초기값 `100`, `1 / 3`, `건설`을 확인한다. `골드 +50`으로 표시 갱신을 확인한다.
3. `다음 시작 거절` 후 `웨이브 시작`을 누르면 메시지가 뜨고 재시도할 수 있어야 한다.
4. 다시 시작하면 `전투 준비` 뒤 `전투`가 된다. 처리 중 연타가 중복 요청을 만들지 않아야 한다.
5. `전투 승리` → 보상 → `계속하기`를 반복한다. 3웨이브 승리 후 최종 결과와 재시작을 확인한다.
6. 재시작 후 `전투 패배` 경로도 확인한다. 재시작 시 골드·웨이브·패널이 초기화되어야 한다.
7. 해상도 1920×1080, 1280×720에서 글자 잘림·패널 겹침을 확인한다.
