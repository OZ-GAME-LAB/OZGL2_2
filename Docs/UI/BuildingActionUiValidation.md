자체 검사는 Unity Test Runner의 EditMode/PlayMode 테스트가 아니다.
Edit Mode에서는 공개 API/버튼 이벤트를 호출하고, 필요한 생명주기 콜백만 reflection으로 재현한다.

## 자동 검사 주요 항목

- 필수 ID/이름/옵션/비용/실패 사유 유효성, null 입력의 부분 적용 방지.
- 연결 담당 없음, 건설 단계 아님, 실행 불가 견적은 클릭해도 요청을 만들지 않음.
- Build/Upgrade/Dismantle의 대상 인스턴스와 옵션 ID 보존.
- 중복 클릭, 대기 중 정보 갱신, 상태 잠금 해제 호출로 재실행되지 않음.
- 잘못된 ID/중복 응답 무시. 재시도마다 새 ID.
- 실패 후 선택 유지/재시도, 성공 후 최신 견적 대기.
- 다른 선택 및 해제 후 같은 선택으로 돌아온 경우에도 이전 결과 문구 무시.
- enable/disable 반복 리스너 중복 없음. 비활성 상태 응답 처리.
- 0골드 견적, 환급 견적 표시, 동기 응답 처리.

## 실제 Play 확인

1. 빈 공간 A: 건설 30골드 표시 → 연속 클릭 → 요청 대기/버튼 잠금.
2. 실패 응답 → 실패 이유 표시/건설 재활성화/선택 유지.
3. 재요청 → 성공 응답 → 전사 훈련소 레벨 1 표시, 업그레이드 50골드와 환급 21골드 표시.
4. 업그레이드 → 성공 응답 → 레벨 2/밸런스 전사(1차), 최대 단계 문구와 업그레이드 잠금.
5. A 해체 요청 → 응답 전 B 선택 → B는 레벨 1로 표시되지만 행동은 잠김.
6. 이전 A 해체 성공 응답 → B 정보 유지/입력 복구. A 재선택 시 빈 공간 표시.
7. 전투 상태 전환 → 건설 잠금/사유 표시, 실제 클릭해도 요청 없음. 준비 복귀 시 활성화.
8. 조건 불가 샘플 → 골드 부족 사유/건설 잠금.
9. 모든 과정에서 HUD 100골드 유지. 실제 건물/유닛/세이브 생성 없음.
10. Play 종료 확인. 런타임 변경을 씬에 저장하지 않음.

이전 `MvpBuildingInfoTest`도 이번 작업 시작 시 Play로 실행했다.
자원/전사/궁사/지원 4종 선택, 전사 레벨 1→2 갱신, 닫기, 재선택, 외부 선택 해제를 확인하고 종료했다.
