# 기획 보드와 현재 UI 대조

검토일: 2026-09-10. 원문: `D:\Downloads\제목 없음.pdf` (대형 보드 1페이지).

PDF에는 초기 구상, 와이어프레임, 담당자 의견, 시스템 연결 제안이 함께 있다. 문서 전체를 단일 확정 사양으로 취급하지 않는다. 아래의 '유지'는 사용자가 앞서 전달한 최신 진행 설명과 일치하는 부분이며, 별도 확인 없이 다른 팀원의 규칙을 확정하거나 수정하지 않는다. 원본 PDF는 변경하지 않았다.

## UI에 반영할 내용

| 구분 | 확인된 내용 | 처리 |
| --- | --- | --- |
| 유지 | 후보 클릭 시 하이라이트, 별도 버튼으로 선택 확정, 미선택이면 포기 | 기존 선택/확정/포기 동작 유지 |
| 이번 반영 | 기본 3회 후보 추출이지만 아티팩트/특성에 따라 후보 수가 늘거나 줄 수 있음 | 3개 고정 입력 제한 제거, 1개 이상 후보 지원 |
| UI 구현 선택 | PDF는 가변 후보 수의 구체적 배치 방식을 정하지 않음 | 기존 카드 크기를 유지하고 한 페이지 최대 3개, 이전/다음 이동. 이는 게임 규칙이 아닌 구현 선택 |
| 유지 | 획득 골드/보석, 후보 이름/등급/효과 표시 | 외부에서 전달한 값만 표시. 지급/계산/효과 적용 없음 |
| 배치 반영 | 중앙 승리 제목, 두 줄 보상, 이미지가 위에 있는 세로 카드 3개, 하단 중앙 선택/포기 버튼 | 승리 UI 영역을 확대 렌더링해 실제 배치와 대조. 기존 임시 색상/폰트 유지, 최종 아트 복제 아님 |
| 연결 원칙 | UI가 선택 결과를 돌려주고, 아티팩트 담당 시스템이 가방에 넣고 효과 적용 | 기존 요청 ID 기반 응답 계약 유지. 실제 시스템용 어댑터는 별도 협의 |

페이지를 바꿔도 전체 후보 기준 선택을 유지한다. 현재 페이지 밖의 후보가 선택되어 있으면 상태 문구에 그 이름을 표시한다. 확정은 선택된 후보 ID를 전달하며, 페이지 이동은 보상 수령이나 게임 진행을 일으키지 않는다. 후보가 1~2개이거나 마지막 페이지가 덜 찼을 때 남는 카드 슬롯은 숨긴다.

0개 후보를 받았을 때의 게임 진행 규칙은 PDF에 확정되어 있지 않다. UI는 빈 목록을 잘못된 입력으로 거절한다. 이때 자동으로 보상을 포기하거나 다음 단계로 넘어가지 않는다. 중복 후보 ID 거절 정책은 기존 계약을 유지하며, 중복 추출을 허용할지는 담당자와 합의가 필요하다.

## 담당자와 합의할 연결 항목

PDF의 연결 제안: `GameFlowController → ItemManager → 아티팩트 관련 코드 → UI → 선택 반환 → 가방 등록/효과 적용`.

- 매 전투 승리 때 UI 요청이 발생하는 실제 코어 위치. 현재 로컬 코어 이벤트는 분기 종료 흐름에 있음.
- 스테이지 타입(일반/정예/보스)과 후보 등급 가중치/후보 수 계산의 소유자.
- 실제 아티팩트 SO와 UI 표시 모델의 변환, 고유 보상/후보 ID.
- `UniTask` 반환형 및 포기/취소/실패의 구분. PDF의 `UniTask<아티팩트 SO?>`는 연결 제안이며 아직 구현된 공용 API로 간주하지 않음.
- 선택 중 새 플레이 시작/보상 취소, 효과 적용 중 오류, 중복 수령 방지.
- 웨이브 종료 트리거(전멸/보스/시간), 유닛 생성/사망 이벤트와 생존 목록 책임.

UI는 현재 `ChoiceRequested`와 `TryResolveRequest` 계약을 사용한다. 실제 담당자 코드가 들어오면 이를 연결하는 어댑터에서 팀의 확정 API에 맞춘다. 이름이 PDF에 등장한다는 이유로 새 매니저를 생성하거나 팀원 코드를 변경하지 않는다.

## 확정으로 적용하지 않은 메모

- 전투 중 지속 충원, 건물별 유닛 복귀, 단계별 충원, 시작 시 일괄 생성: 복수 대안이 함께 있음.
- 액티브 스킬 개수/마나 수치, 제단 해금과 포인트 세부 수치: 도식과 의견을 곧바로 최종 값으로 해석하지 않음.
- 분기 종료 시 계속/종료 선택과 무한 진행 조합: 앞서 전달받은 최신 설명에서 검토 중인 내용.
- 혈석 정산 예시의 점수, 배율, 게이지와 반올림: 최종 공식으로 확정하지 않음.
- 보석의 정예/보스 보상량, 건물 해체 70%, 업그레이드 조건: 예시/임시/협의 여부를 확인한 뒤 적용.
- 스폰/런타임 유닛 관리자 명칭과 담당자 의견: 현재 코드/팀 협의와 대조 필요.

이벤트 UI의 긍정 초록/부정 빨강/무작위 노랑, 아티팩트 배낭의 정보 팝업, 상점, 제단/특성/토템, 최종 정산 연출은 향후 UI 작업 참고 사항이다. 이번 가변 후보 지원에 포함해 임의로 구현하지 않았다.
